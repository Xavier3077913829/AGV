# AGV 智能调度系统 —— 算法答辩讲稿

> 使用者：算法负责人。建议现场按「地图 → 路径 → 单机排序 → 多机优化 → 时间窗」这条主线讲，
> 每讲一个算法都遵循同一句式：**解决什么问题 → 用什么方法 → 怎么实现 → 复杂度 → 局限在哪**。

---

## 0. 一句话总览

系统是「**Django + Vue3 的 AGV 智能调度平台**」，算法分四层：

| 层 | 模块 | 算法类型 |
| --- | --- | --- |
| 决策层 | `SchedulingDecision` | 图论（Dijkstra）+ 组合优化（DP / 最近邻+2-opt / 最优插入 + VND）+ 时间窗约束 |
| 感知层 | `ManufacturingVision` | 传统 CV（Frangi 黑脊、形态学、Hu 矩形状匹配） |
| 监测层 | `EquipmentMonitoring` | 机器学习（StandardScaler + RandomForest）+ 物理阈值规则 |
| 预测层 | `DemandForecast` | 时间序列（移动平均 / Holt-Winters / ARIMA）+ 回测选优 |

## 1. 调度模块（核心，讲 60% 时间）

### 1.1 地图建模：邻接表有向图

```python
graph = { node_id: [(neighbor_id, distance, speed_limit), ...] }
```
- 数据来自数据库三张表：`MapNode`（节点）、`MapRoad`（道路）、`MapObstacle`（障碍）
- 障碍物会把两端节点剔除 → **动态图**（这也是"要不要缓存"的关键）

### 1.2 路径规划：Dijkstra（堆优化）+ 结果缓存

**实现要点**（`GraphRouter`）：
- `heapq` 优先队列 + `distances` 字典 + `visited` 集合 + `previous` 前驱
- 弹出终点即 `break`（不必跑完全图）
- `path(start, end)` 命中 `cache[(start,end)]` 直接返回

**复杂度**：
- 单次 Dijkstra：`O((V + E) log V)`
- 有缓存后：同一 OD 对摊薄为 `O(1)`
- 本系统 V、E 都是几十级 → 单次亚毫秒

**为什么不用 A\***：地图规模极小，Dijkstra 已经足够快；A\* 需要可采纳启发式（欧氏距离可用），
但收益只在长距离路径上体现，代码复杂度上升不值得。**这是我们主动做的取舍，不是不会。**

**为什么敢缓存**：仓库路网在两次"地图变更"之间是静态的；
`plan_shortest_path` 里修改地图（增删节点/道路/障碍）会**清空缓存**——这点老师一定会问。

### 1.3 任务路线：两段路径拼接

`_plan_task_route`：`起点 →取货点` 与 `取货点 →放货点` 各跑一次 Dijkstra，用 `_join_paths` 拼接
（去掉重复的接点），得到完整路线 + 总距离 + 时间轴。

### 1.4 时间窗避碰（★ 系统最有"多机器人"味道的一段）

数据结构：
```python
reservations = { node_id: [ {start, end, agv_id, task_id}, ... ] }
```

`_resolve_node_wait` 的逻辑：
1. 本车到达节点的时间是 `arrival`，占用窗口 = `[arrival, arrival + SAFETY_GAP]`
2. 把该节点已有的预约区间**按开始时间排序**
3. 若与某区间重叠 → 顺延到 `interval.end + SAFETY_GAP`，再继续向后检查
4. 返回"需要等待的秒数"，计入时间轴

**语义**：**节点级独占 + 安全间隔**，本质是简化的「资源时间窗（time window）」调度。

**必须承认的局限**（被问就用这段话）：
> 我们只做了**节点冲突**，没有显式建模**边冲突（两车相向占用同一路段）**和**循环等待死锁**。
> 缓解手段是节点独占 + 安全间隔，实际演示中没有出现死锁；
> 若要严格保证无死锁，需要引入资源排序（死锁避免）或预约边+回退机制 —— 这是我们下一步方向。

### 1.5 单台 AGV 多任务排序：小规模精确 DP，大规模启发式

`optimize_single_order`：

| 任务数 | 方法 | 说明 |
| --- | --- | --- |
| `n ≤ 10` | **状态压缩 DP** | `dp[(mask, last)] = (最小代价, 路径)`，状态 `2^n·n`，转移 `n` → `O(n²·2ⁿ)`；n=10 约 10 万次转移，**得到全局最优** |
| `n > 10` | **最近邻构造 + 2-opt 改进** | 先贪心排一个初始序，再用 2-opt 反转子段消交叉，`O(n²)`/轮 |

**为什么要 DP**：单车任务数本来就少（仓库一趟最多十几单），精确最优的代价可以接受；
而且**DP 的结果可以作为大规模启发式的"基准答案"**（小规模验证启发式质量）。

### 1.6 多台 AGV 联合调度：最优插入 + 变邻域下降（VND）

**① 初始化 —— 最优插入（`build_insertion_solution`）**
对每个任务，遍历「所有 AGV × 所有插入位置」，选目标函数最优的位置插入。
相当于把「任务分配」和「车内顺序」同时做贪心，比"按优先级塞给最早完成的 AGV"好得多。

**② 改进 —— VND（`improve_solution_vns`）**
四个邻域轮流用，**首次改进即接受**，一旦改进就回到第一个邻域重新搜：

| 邻域 | 动作 | 作用 |
| --- | --- | --- |
| **relocate** | 把 1 个任务搬到本车其他位置或别的车 | 消除"塞错车" |
| **swap** | 交换两个任务（同车或跨车） | 调整优先级 |
| **or-opt** | 把 2~k 个**连续**任务整体搬走 | 保持成组任务的顺序 |
| **2-opt** | 反转同车一段连续任务 | 消除路线交叉 |

- 终止条件：四个邻域都无改进，或达到 `max_rounds=50`
- 邻居数 > `max_neighbors=350` 时**固定种子随机采样** → 结果可复现（这点会被问）
- 与基线 `build_baseline_solution`（按优先级取"最早完成"的 AGV 追加）对比出提升

**③ 目标函数 —— `evaluate_solution`**
加权综合：完成时间、总距离/能耗、等待时间、超时惩罚；并检查**可行性**：
- AGV-任务兼容性（`_is_agv_compatible`：载重/类型）
- **电池约束**（剩余电量要够跑完全程）
- 时间窗冲突（上面的预留表）

**为什么不直接上精确求解（MILP / CP-SAT）**：
> 多车多任务带时间窗属于 **VRPTW 家族，是 NP-hard**。
> 精确求解在几十任务时虽然可行，但**依赖重型求解器、求解时间不可控**，而调度接口要求秒级响应。
> 所以我们选「构造 + 局部搜索」：响应快、结果可解释、基线与提升可量化。
> 如果任务规模进一步扩大，我们已验证可以平滑替换为 OR-Tools 的 CVRPTW 求解器（见第 5 节）。

## 2. 视觉模块（传统算法，无深度学习）

### 2.1 裂纹检测：Frangi 黑脊响应（多尺度）

**数学原理**：
对图像做尺度 σ 的高斯二阶导，得到 **Hessian 矩阵** `H = [[hxx, hxy],[hxy, hyy]]`，
其两个特征值 `λ1, λ2`（|λ1| ≤ |λ2|）刻画局部曲率：
- 线状结构（暗线、两侧亮）→ **|λ1| 很小、|λ2| 较大且 > 0**
- 块状/角点 → 两个方向曲率都大 → 被抑制

**实现**（`_vesselness_map`）：
1. 用 `cv2.sepFilter2D` 做**可分离卷积**：`hxx`（x 方向二阶）、`hyy`（y 方向二阶）、`hxy`（x 一阶 × y 一阶）
2. 2×2 对称矩阵特征值**闭式解**：
   ```
   root = sqrt((hxx - hyy)² + 4hxy²)
   λ1 = (hxx + hyy - root)/2,  λ2 = (hxx + hyy + root)/2
   ```
3. 响应函数：
   ```
   Rb  = |λ1| / |λ2|                    ← 线状性（越小越线状）
   S   = sqrt(λ1² + λ2²)                ← 结构强度
   V   = exp(-Rb²/(2β²)) · (1 - exp(-S²/(2c²)))
   ```
   前半项抑制块状结构，后半项抑制噪声弱响应；`c` 取该尺度最大幅值的一半（自适应阈值）
4. **多尺度取 max**（`sigmas` 如 1.5/2.5/3.5）→ 适应不同宽度的裂纹

**后处理**（`analyze_crack`）：
- 阈值化 → `connectedComponentsWithStats` 连通域
- 过滤：**边界 margin**（贴边的不算，避免边框干扰）、面积下限、长宽比（细长才像裂纹）
- 输出：检测框、掩膜、判定结果、耗时

**为什么不用深度学习**：
> 产线缺陷样本极少、缺陷形态事先未知；传统算法**免训练、毫秒级、可解释**
> （能说清楚"为什么判定为裂纹：这里有一条暗的细长结构"）。
> 这也为后续引入无监督深度模型（PatchCore）留出了对照基线。

### 2.2 工件识别：形态学分割 + 形状分类

流程：
1. **双边滤波**（保边去噪）→ **Otsu 自适应阈值** → 前景占比 > 0.5 时反相
2. **开运算 + 闭运算**（椭圆核）去掉噪点、填小孔
3. `findContours` → 面积筛选 → `approxPolyDP` 多边形近似
4. **分类依据**：顶点数 + **圆度** `4πA/P²` + **Hu 矩形状相似度**（`cv2.matchShapes`，旋转/尺度不变）
5. `_confidence` 综合三项给置信分；`_shape_templates` 用理想形状模板做相似度打分

### 2.3 新增：Anomalib PatchCore（无监督缺陷检测，已集成）

- 只用**正常样本**训练：提取局部特征 → coreset 采样建"记忆库"
- 推理：对每个像素块找最近邻距离 → **图像级异常分数 + 像素级热力图**
- 与 Frangi 互补：**Frangi 给可解释的线状证据，PatchCore 抓未知类型缺陷**
- 数据已转成 MVTec-AD 布局（正常 100 / 裂纹 57 / 掩膜 57）

## 3. 设备监测模块：随机森林 + 物理规则双轨

**特征（5 维）**：`temperature_c, vibration_mm_s, current_a, spindle_speed_rpm, tool_wear`

**模型**：`Pipeline(StandardScaler → RandomForestClassifier(n_estimators=260, max_depth=10, class_weight="balanced"))`
- 三分类：`normal / fault / worn`（AI4I 数据集：9652 / 302 / 46，**严重不平衡**）
- `class_weight="balanced"` + 树模型 → 对小类有基本保障
- 输出：类别标签 + `predict_proba` 置信度 + 特征重要性

**规则告警（`_rule_alerts`）**：

| 指标 | 阈值 | 级别 |
| --- | --- | --- |
| 温度 | ≥ 74 ℃ | warning |
| 振动 | ≥ 3.1 mm/s | **danger** |
| 电流 | ≥ 6.2 A | warning |
| 刀具磨损 | ≥ 0.78 | **danger** |
| 主轴转速 | ≤ 1415 rpm | warning |

**为什么"模型 + 规则"双轨**：
> 模型给统计判断（能处理多变量耦合），规则给**物理红线**（可解释、可追责）。
> 两条线互补：模型漏报时规则兜底，规则误报时模型降级判定。

**实测（我们跑的）**：RF ROC-AUC **0.9429**、F1 **0.5677**（异常率 3.48%）；
对比无监督 PyOD-ECOD：ROC-AUC 0.8288。
> F1 偏低是**极不平衡**导致的正常现象；报告里应同时看 **PR-AUC**，并说明"以召回优先"。

## 4. 需求预测模块：三模型回测选优

| 模型 | 原理 | 适用 |
| --- | --- | --- |
| 移动平均 | 最近 k 期均值外推 | 平稳、强基线 |
| Holt-Winters | 水平 + 趋势 + 季节 三指数平滑 | 有趋势和周期（订单通常有周周期） |
| ARIMA/SARIMA | 差分自回归移动平均 | 自相关结构强 |

**自动选优（`forecast_demand`）**：
1. `_infer_frequency` 按日期间隔推断频率与季节周期（日数据 → 周期 7，MA 窗口自动定）
2. 留出最后 `≥7` 期做**回测**（训练集至少 20 期）
3. 每个候选模型算 **RMSE / MAPE** → 选误差最小的
4. 用**全量数据重训**该模型 → 预测未来 `horizon` 期

**为什么这么做**：订单量小且非平稳，单一模型不可靠；回测选优让系统"自己挑最合适的"。

**局限（主动承认）**：长 horizon 下 ARIMA 置信区间发散；未做 SKU 级层级预测（只能整体汇总）。

## 6. 答辩高频问题 & 标准回答

| # | 问题 | 回答要点 |
| --- | --- | --- |
| 1 | Dijkstra 复杂度？为何不用 A\*？ | `O((V+E)logV)`；图仅几十节点，A\* 收益有限、徒增复杂度；已预留扩展位 |
| 2 | 缓存会不会导致结果错？ | 缓存只在路网不变期间有效，增删节点/道路/障碍会清空 |
| 3 | 时间窗能防死锁吗？ | **不能严格防**：只做节点独占，未建模边冲突/循环等待；缓解=安全间隔，下一步=资源排序或边预约 |
| 4 | DP 为什么限制 10 个任务？ | 状态 `2ⁿ·n`、转移 `n`；n=10 约 10 万次，n=13 就 80 万+且每次要查路径 → 收益下降 |
| 5 | VND 能保证最优吗？ | 不能，是局部搜索；但小规模下与 DP 精确解对比验证过质量，且有基线提升数据 |
| 6 | 目标函数权重怎么定？ | 权重可配；完成时间/距离/等待/超时分别归一化后加权，避免量纲问题 |
| 7 | Frangi 的 β 是什么？ | 控制"线状 vs 块状"的敏感度，β 越小越只保留细长结构（经典取 0.5） |
| 8 | 多尺度 σ 怎么选？ | 覆盖待检裂纹宽度（约 2~8 px），取各尺度响应最大值 |
| 9 | 裂纹误检怎么压？ | 连通域长宽比 + 面积下限 + 边界 margin 三重过滤 |
| 10 | 工件识别怕光照吗？ | Otsu 对光照敏感；用双边滤波 + 形态学缓解，承认局限；可升级为自适应阈值/深度分割 |
| 11 | 为什么不用深度学习做设备监测？ | 数据 1 万行、5 维特征、要求可解释与轻部署；RF 已 0.94 AUC |
| 12 | 类别不平衡怎么办？ | `class_weight="balanced"`；报告应看 **PR-AUC/召回**，可加 SMOTE 或代价敏感学习 |
| 13 | ARIMA 阶数怎么定？ | statsmodels 自动定阶 + 回测挑模型 |
| 14 | 为什么用 MAPE？ | 业务可解释（百分比误差）；但对接近 0 的真值敏感，故同时报 RMSE |
| 15 | 系统实时性怎么保证？ | 路径缓存 + VND 邻域上限 350 + 固定种子采样；单次调度亚秒级 |

## 7. 现场演示建议（3 分钟版）

1. **地图与路径**：放 2 个障碍 → 展示"路径绕行"，说明 Dijkstra 在动态图上工作
2. **单车多任务**：5 个任务 → 展示 DP 最优顺序（可对比最近邻的差异）
3. **多车联合**：10 个任务 3 台车 → 展示 VND 相对基线的指标提升（表格里那几列）
4. **时间窗**：把安全间隔调大 → 展示"等待秒数"出现在时间轴上
5. **视觉**：一张裂纹图 → 原图 / 掩膜 / 判定结果三连
6. **设备**：一段异常序列 → 类别 + 置信度 + 规则告警
7. **预测**：14 天预测 → 三模型误差对比表

**准备 3 个数字**：Dijkstra 缓存命中率、VND 相对基线提升 %、RF 的 ROC-AUC。

## 8. 三句话收尾（背下来）

> 1. 调度层是「图论 + 组合优化」的组合：Dijkstra 保证路径最优，DP/VND 在秒级内把多车多任务排好。
> 2. 感知层坚持「可解释的传统算法 + 可对照的无监督深度模型」，两种证据互相校验。
> 3. 监测与预测层用「物理规则 + 统计模型」双轨，既能量化也能追责。
