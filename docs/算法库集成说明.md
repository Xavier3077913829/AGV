# 算法库集成说明（2026-10）

本目录是在原 `AGV` 项目（Django + DRF + Vue3 智能调度/视觉/监测/预测系统）基础上，
集成三套开源算法库形成的算法增强版本。

## 一、集成了什么

| 库 | 版本来源 | 许可证 | 放进哪里 | 用在哪 |
| --- | --- | --- | --- | --- |
| **tsfresh** | `vendor/tsfresh`（GitHub main） | MIT | 源码随项目 | 设备监测：**时序特征自动提取** |
| **PyOD** | `vendor/pyod`（GitHub master） | BSD-2 | 源码随项目 | 设备监测：**多模型无监督异常检测**（IForest/ECOD/HBOS/LOF/COPOD） |
| **anomalib** | `vendor/anomalib`（GitHub main） | Apache-2.0 | 源码随项目 | 视觉检测：**PatchCore 无监督缺陷检测**（图像级+像素级） |

> 三个库都以**源码形式**放在 `vendor/`，可用 `pip install -e ./vendor/<name>` 安装，
> 离线环境也能装（无需联网）。这比复制 pip 缓存更透明，便于答辩时说明算法出处。

## 四、跑实验（生成报告数据）

```bash
python scripts/bench_anomaly.py        # 输出 runs/bench_anomaly.csv
python scripts/bench_features.py       # 输出 runs/tsfresh_features.csv
python scripts/prepare_anomalib_dataset.py
python scripts/train_patchcore.py
python scripts/bench_patchcore.py
```

`bench_anomaly.py` 会在 AI4I 设备数据（`datasets/equipment/ai4i_equipment.csv`）上
同口径比较 **RandomForest 基线**与 **PyOD 五个无监督检测器**，输出 ROC-AUC / F1 表，
可直接放进报告作为"算法依据"的实测支撑。

## 七、注意

1. `vendor/` 里是**上游源码快照**，升级请重新下载而不是手改；
2. `anomalib` 依赖 PyTorch + Lightning，安装包较大（数百 MB），首次安装需耐心；
3. 前端 `node_modules` 未包含（压缩时已排除），恢复请 `cd frontend && npm install`；
4. 若离线安装失败，可先用 `scripts/check_algo.py` 确认缺哪个，再单独处理。

## 八、⚠️ 算法已接入业务接口（2026-10 更新）

三个库不是"放着跑实验"，而是**接成了项目正式 API**（DRF `APIView`），路由已注册。

### 8.1 设备监测（PyOD + tsfresh）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/equipment/algo/status/` | 依赖可用性 |
| POST | `/api/equipment/algo/detect/` | **PyOD 无监督异常检测**（IForest/ECOD/COPOD/HBOS/LOF） |
| POST | `/api/equipment/algo/features/` | **tsfresh 自动特征**（返回窗口数/特征数/矩阵） |
| POST | `/api/equipment/algo/compare/` | **RF 基线 vs PyOD 多模型**对比表 |
| POST | `/api/equipment/algo/diagnose/` | **原 RF 诊断 + PyOD 异常分数融合**结果 |

### 8.2 视觉检测（anomalib）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/vision/algo/status/` | anomalib 是否可用 + 数据集统计 |
| POST | `/api/vision/algo/dataset/` | 把 `datasets/vision/mt` 转成 **MVTec-AD 布局** |
| POST | `/api/vision/algo/patchcore/` | **PatchCore 推理**（上传图片，未装 anomalib 返回 503） |

### 8.3 调用示例

```bash
# 依赖状态
curl http://127.0.0.1:8000/api/equipment/algo/status/

# 异常检测（用项目内置数据集，limit 越大越准，10000 为全量）
curl -X POST http://127.0.0.1:8000/api/equipment/algo/detect/ \
  -H "Content-Type: application/json" \
  -d '{"dataset":"ai4i_equipment","limit":10000,"method":"ECOD"}'

# 对比实验（生成报告表格）
curl -X POST http://127.0.0.1:8000/api/equipment/algo/compare/ \
  -H "Content-Type: application/json" -d '{"dataset":"ai4i_equipment","limit":10000}'

# tsfresh 特征
curl -X POST http://127.0.0.1:8000/api/equipment/algo/features/ \
  -H "Content-Type: application/json" -d '{"dataset":"ai4i_equipment","window":64}'

# 视觉数据集转换
curl -X POST http://127.0.0.1:8000/api/vision/algo/dataset/ \
  -H "Content-Type: application/json" -d '{}'

# PatchCore 推理（需先装 anomalib）
curl -X POST http://127.0.0.1:8000/api/vision/algo/patchcore/ -F "file=@test.jpg"
```

### 8.5 设计原则（答辩可讲）

1. **懒加载**：三个库未安装时项目照常启动，接口返回 503 + 安装提示，不影响原有功能；
2. **不改老逻辑**：原 `diagnose/`、`crack/`、`predict/` 等接口行为完全不变；
3. **融合而非替换**：`algo/diagnose/` 在同一次响应里同时给出 RF 结论和 PyOD 异常分数，
   让"有监督 + 无监督"两路证据可以互相校验；
4. **实测验证**：`manage.py check` 通过，5 个接口用 Django 测试客户端实调返回 200。
